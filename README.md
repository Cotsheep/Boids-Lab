# BoidsLab

> 开发机曾在 Godot 图形操作时蓝屏。2026-10-27 用户更新显卡驱动后，简单测试暂未复现；长期稳定性尚未验证。详细诊断记录保存在本地，不随源码上传。

用于团队技术分享和个人学习的 2D Boids 实验框架。运行环境为 **Godot 4.7.2 .NET + .NET 8 SDK**，语言为 C#。

当前已实现 UI、配置、按数量与种子生成个体、速度/加速度积分、受角速度和角加速度限制的朝向跟随、越界环绕、可切换的朴素/均匀网格邻居搜索与实测统计，以及**分离、对齐、聚集三条群集规则**。支持单选高亮、选中个体的感知范围与邻居连线、全体运动方向调试绘制，以及可编辑的矩形、圆形障碍物与避障。

结构参考 [SebLague/Boids 的管理器](https://github.com/SebLague/Boids/blob/fdda4db1368df92fbacd8a644bbe6dc61d705441/Assets/Scripts/BoidManager.cs)与[个体脚本](https://github.com/SebLague/Boids/blob/fdda4db1368df92fbacd8a644bbe6dc61d705441/Assets/Scripts/Boid.cs)：`BoidManager` 统一调度，每只 `Boid2D` 保存自身状态并提供普通更新方法，外观由各自场景中的 `Polygon2D` 显示。当前没有引入 GPU 计算。

项目采用普通全窗口游戏的结构：`Game (Node)` 下分别放置 `World (Node)` 与 `UI (CanvasLayer)`。Node2D 世界直接显示在根视口中，Control 面板作为 HUD 覆盖在世界画面上；未来可以在同一个 World 容器中接入 Node3D 场景，复用 UI。当前尚无 3D 场景或算法。

## 打开和运行

1. 使用 Godot **4.7.2 .NET 版**导入本目录的 `project.godot`。已有项目目录仍为 `boids`，应用和程序集名称为 `BoidsLab`。
2. 在编辑器中构建 C# 项目，然后按 F6 运行 `scenes/main.tscn`，或按 F5 运行主场景。
3. 也可以先在本目录运行 `dotnet build BoidsLab.csproj`，再由编辑器启动。

初始窗口为 1360 × 860，最小为 960 × 640。这里的“全窗口”指游戏世界使用整个根视口，不切换操作系统的独占全屏模式，也没有修改原生窗口模式。HUD 顶部显示标题和状态，左侧参数面板可滚动，底部统计项可换行。空白 UI 和提示文字不拦截鼠标，有交互的面板与控件正常接收输入；参数面板内滚动不会同时缩放相机。使用 Compatibility 渲染器，无第三方插件或素材依赖；原有 Godot 图标保留。

启动时按配置生成个体，初始为暂停状态。“个体数量”和“随机种子”修改后在**重置**时生效；相同种子、数量、当前模拟边界与最大速度能在当前引擎版本中复现初始状态。每只个体在当前视野内随机选择初始位置和方向，初始速率为最大速度。运动上限修改后在下一次运行更新时生效；有规则转向目标时，最大速度也用作目标速率，没有邻居时不会仅因为提高速度上限就自动加速。

`Boid2D.SetAcceleration(Vector2)` 保留为持续的外部加速度输入，传入 `Vector2.Zero` 撤销。每步群集转向单独传入 `UpdateBoid(delta, steeringAcceleration)`，与外部输入相加后限制总加速度；规则不会覆盖外部输入，也不会把上一帧转向残留到下一帧。角加速度只控制外观朝向平滑跟随实际速度方向，不直接旋转速度向量。具体公式与调用示例见 [架构说明](docs/architecture.md)。

## 障碍物编辑与避障

在“障碍物”面板选择添加矩形或圆形，再点击世界画面放置。放置后自动选中并显示高亮边框和缩放手柄。拖动本体移动；矩形右下角手柄分别调整宽高，圆形右侧手柄调整直径。面板提供对应尺寸输入，也可将鼠标放在选中障碍物上，用 Shift + 滚轮等比缩放。正常滚轮仍用于相机缩放。尺寸范围统一为 16–2000 世界像素。

暂停和运行时均可创建、选择、编辑和删除障碍物。障碍物与 Boid 的选择互斥；操作 UI 不会拖动世界或误删障碍物，编辑输入框时 Delete 只编辑文字。F2 弹窗会结束未完成的放置或拖动，并拦截背景输入。重置只重新生成鸟群，保留障碍物；障碍物布局当前仅属于本次运行，不保存到配置文件。

避障独立于分离、对齐、聚集三条群集规则。开启时沿当前速度提前检查障碍物，必要时优先避让。“前瞻时间”默认为 0.75 秒，“避障间距”默认为 12 世界像素；间距以个体中心到障碍物表面的距离计算。障碍物固定在世界坐标中，不随 Boid 环绕，也不会因相机缩放而改变实际尺寸。

运动时还会扫描本步路径，接触障碍物时截断位移并保留沿表面的速度，避免高速直接跨过薄障碍。新增或放大障碍物造成的重叠也会尝试移出。关闭避障会同时关闭转向和接触约束。矩形角部采用保守留距；障碍物相互重叠或封满整个视野时，不保证存在可退出的自由位置。这不是刚体物理系统。

## 三条群集规则

- **分离**：避开分离半径内的近邻，越近的邻居对分离方向影响越大。新增分离半径默认 25，实际范围取它与感知半径的较小值。
- **对齐**：朝感知范围内邻居的平均速度方向转向，目标速率为最大速度。
- **聚集**：朝邻居中心靠拢；中心方向由最短环绕位移的平均值计算，跨屏幕边界时也正确。

三条规则各自转换为受限加速度，乘以权重后求和，再限制总模长。关闭某条规则或将其权重设为 0，可消除它在下一步的贡献；无群集转向、避障或外部加速度时保持惯性运动。没有最小速度限制。完全重合的个体会根据 ID 确定相反分离方向，避免除零。此实现是转向行为，不是保证个体之间互不穿透的碰撞系统。

模拟边界 `WorldBounds` 等于**相机当前可见的世界矩形**，背景和网格覆盖同一区域。缩放、拖动和视口尺寸变化后立即同步边界；落在新边界外的个体会环绕回画面内，包括暂停状态下的视角操作。此过程保留个体数量、速度和朝向。重置会在当前视野中重新生成个体。

`BoidManager.WorldSize` 的 1280 × 720 仅作为初始与 Home 复位的参考尺寸；相机按窗口比例适配这个参考矩形，实际模拟区域可以更宽或更高。参考尺寸不随动态边界改变，避免缩放被重新适配抵消。网格仍按固定世界坐标绘制，拖动时不会附着在屏幕边缘。HUD 遮住的区域仍属于世界，隐藏 HUD 不改变边界。参数里的“像素”指世界像素（px），经过缩放后不一定对应一个屏幕像素。

## 选择与调试观察

左键按下时记录命中的个体，松开且移动不足 5 个视口像素时确认选择，因此运行中的个体即使已经移开，也能被选中。超过阈值则平移相机，不改变选择；从 UI 控件开始的操作只影响 UI。命中测试使用实际三角形，同时保留 10 个视口像素的点击容差，缩小时仍可点击。选中个体显示金色外观和圆环，取消后恢复原始颜色；重置或移除该个体会清除选择。

青绿色圆弧表示选中个体的感知范围，加粗为 3 个视口像素；橙色圆弧表示其实际分离范围，线宽为 2 个视口像素。两种范围可独立开关，缩放时保持屏幕线宽。蓝色箭头表示全体个体的实际速度方向，金色连线只表示选中个体的邻居。没有选中对象时，不生成范围和连线；范围圆的生成成本不随群体数量增长。箭头长度随速率变化并限制在 8–80 个视口像素，便于观察方向，不作为精确速度标尺。圆弧和连线在环绕边界处延续到另一侧；某种范围覆盖整个环绕世界时，用对应颜色的世界边框表示。

连线依据**当前画面上的位置**查询，不依赖上一物理步的缓存，因此暂停、首次开始前、改变半径或调整相机后都能立即查看。它只对选中个体做一次 O(N) 距离扫描，不修改模拟搜索结果或性能统计。调试绘制开销会影响 FPS，但不计入模拟更新/搜索耗时。各显示开关会保存，选择状态不保存；隐藏 HUD 后仍可选择并查看已开启的调试显示。

## 邻居搜索与性能对比

每次物理更新先复制所有个体的位置与速度，再搜索邻居、计算所有个体的转向，最后统一移动。邻居按最短环绕距离判断：包含恰好位于感知半径上的个体与重合位置的其他个体，不包含自身。两种方式输出相同的邻居集合，遍历顺序可以不同；转向会有浮点累加顺序造成的微小差异，不承诺长期轨迹逐位一致。

- **朴素遍历**：每个个体检查所有其他个体，每步距离检查次数为 `N × (N − 1)`。
- **均匀网格**：每步重建空间格子，只检查自身与相邻格中的候选，再进行同样的距离判定。格子随感知半径及当前边界划分，支持跨边界查询。屏幕上间距 40 像素的辅助网格与它独立。

候选检查次数按有向查询计算，甲检查乙和乙检查甲分别计数，不包含自身或格子查找。平均邻居数是所有个体的邻居数之和除以实际数量，空群体测量后为 0。搜索耗时包含快照、网格构建、距离检查和结果写入；模拟更新耗时还包含群集转向、避障、运动积分、接触约束及环绕，不含渲染。界面每 0.25 秒显示最近一次物理步的读数，并非累计或窗口平均。

暂停会保留最后一次测量。重置、增删个体、修改搜索方式/半径或相机边界后，旧结果失效，统计恢复 `--`，下一次运行更新重新测量。

对比时可先将最大速度设为 0，固定数量、种子、半径与相机位置后重置，开始运行并切换搜索方式。这样两种算法处理的是相同的静止分布；跳过首次测量，多观察几次耗时和候选次数。移动场景应保持相同初始条件与运行步数。FPS 同时受节点绘制与界面开销影响，不能单独代表搜索效率。网格在分布较均匀、局部邻居较少时减少候选；个体密集或半径覆盖整个区域时仍可能退化到二次复杂度，没有保证的固定加速倍数。

参数控件在 `ControlPanel.Bind()` 中生成；HUD 布局在 `main.tscn` 的 `UI/UIRoot` 分支中编辑，操作说明内容在 `scenes/ui/help_overlay.tscn` 中编辑，世界与相机在 `boids_world_2d.tscn` 中编辑。`BoidManager` 是世界根节点，负责生成、统一更新、边界环绕和计时；`Boid2D` 保存自身运动状态并完成积分，`boid_2d.tscn` 中的 Polygon2D 跟随节点变换显示三角形。`SimulationView` 负责背景、网格和调试绘制入口；`SimulationCamera2D` 处理拖动、缩放、全景复位和视口适配。主控制器通过 `ISimulationWorld` 操作世界，未来可接入实现该接口的 Node3D 场景。详见 [架构说明](docs/architecture.md)。
