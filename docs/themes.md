# 冰岩明暗主题与调色资源

更新日期：2026-11-02。以冰岩作坊的橙色方向设计；以下色值为本项目的设计选择。

顶部「明色 / 暗色」按钮表示当前主题，点击切换并自动保存。明色「晴白杏橙」采用清透暖白背景、白色面板和杏橙障碍，避免大面积灰褐色。暗色「炭灰焰橙」以炭灰衬托明亮杏橙。主要操作使用鲜橙底和深色文字。

## 在 Godot 中调色

- 明色资源：`res://themes/bingyan_light.tres`。
- 暗色资源：`res://themes/bingyan_dark.tres`。
- 资源类型：`LabPalette`，可在 Inspector 中编辑；主场景 Game 的 `LightPalette` / `DarkPalette` 槽引用这两份资源，也可以替换为复制后的配色资源。

选择资源后，颜色按「界面底色」「文字与状态」「强调与交互」「个体身份」「场景与障碍」「调试可视化」分组。保存资源后，下次运行使用新颜色，无需修改或重新编译 C#。`IsLight` 区分明暗显示方式，应保持与资源用途一致。

运行中可在 **Remote Inspector → Game → LightPalette / DarkPalette** 展开资源修改颜色，画面立即刷新，普通个体、淡化材质、障碍及正在移动的放置预览同步变化。Remote Inspector 的修改只对本次运行生效；确定颜色后需回到本地资源填写并保存，才能保留到下次运行。

| 常调属性 | 作用 |
| --- | --- |
| Canvas / Panel / Input | 世界背景 / 界面面板 / 输入框底色 |
| Accent / OnAccent / AccentText / AccentWash | 主操作底色 / 按钮文字 / 强调文字 / 页签底色 |
| Boid / Selection / Leader / SelectedLeader | 普通个体 / 选择 / 领队 / 三维选中领队 |
| Obstacle / ObstacleSelected / ObstacleOutline | 已放置障碍的填色、选择填色和轮廓 |
| ObstaclePreview / ObstaclePreviewOutline | 放置初始预览及其轮廓，独立于感知范围颜色 |
| Grid / Frame / Perception / Separation / Velocity | 网格、边框及各类调试几何 |

## 状态与实现

外观选择独立保存到 `user://boids_lab_ui.cfg` 的 `appearance/light_theme`；它只保存明 / 暗选择，颜色由项目中的 `.tres` 资源定义。缺失字段或无效类型使用默认暗色；读写失败会显示提示。两套模拟配置不因主题改变。

按钮切换前提交当前数值草稿；Remote Inspector 调色不提交草稿。调色不重置、单步或暂停模拟，不改变相机、运动、身份、障碍位置、分类和滚动位置。新生个体和重置继承当前主题。领队和选择高亮仍优先于近距离淡化。

`LabPalette` setter 发出 Changed，`MainController` 更新控件主题和当前视图。每个三维世界共享四份主题材质，主题变化时更新颜色并重建淡化缓存，不逐个体复制材质，也不修改源场景材质。场景中保留的静态颜色仅供编辑器或独立个体预览兜底，运行世界统一使用配色资源。

## 验证

`theme_checks` 包含 169 项断言，覆盖文字对比度、图形对比度、原生资源保存与加载、复制隔离、Remote Inspector 等价属性修改、明暗预览初始颜色及中途切换、已放置障碍的颜色与轮廓、二维 / 三维个体与淡化、重启、状态隔离。默认配色中，测试所列正文、主要语义文字及其指定底色的对比度至少 4.5:1；个体身份、感知、分离与速度颜色对世界背景至少 3:1。参考网格、边框、障碍填色及禁用文字不属于上述保证范围；用户自行修改的颜色不会被自动修正。当前总结果见[验证记录](3d-implementation-validation.md)。

固定场景 `tests/diagnostics/palette_visual.tscn` 通过 Godot MCP 使用 Compatibility 渲染器生成两种主题下矩形、圆形、长方体、球体的 8 张画面，包含普通个体、放置预览和已有障碍。输出位于 `.godot/validation/palette/`，不读写用户配置、不捕获鼠标、不使用 Computer Use。图形输出用于检查实际颜色，不代替完整交互验收。
